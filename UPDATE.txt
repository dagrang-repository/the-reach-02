THE REACH 02 - REVISION 3 (25 November 2026) - follows "Calling AI Models", the site-agnostic playbook, Revision 3

HOW IT GOES LIVE
   A push to main: GitHub deploys the Worker, then sweeps it (deploy.yml). No migration: new tables and columns
   create themselves on first use. The packs of the doors reach their sites with tools\pack-install.ps1 -Apply,
   then tools\pack-deploy.ps1 -Apply (DEPLOY.md, "Per-site packs").

WHAT CHANGED (Revision 3)
   The hub's own surface
   - MCP server card at /mcp/server-card (type application/mcp-server-card+json), same bytes at the three older
     paths. server/discover answers the 2026-07-28 shape (supportedVersions, ttlMs, cacheScope, serverInfo in
     _meta); the endpoint now also lists and reads resources. Server version 1.2.0.
   - A2A 1.0: the card carries supportedInterfaces, the endpoint answers SendMessage in the 1.0 wire and still
     answers message/send for 0.3 clients; an unspoken version is -32009 with the list of what is spoken.
   - One catalog at /.well-known/ard.json and /.well-known/ai-catalog.json: urn:air: identifiers, media types,
     2 to 5 user questions per entry, one entry per door. Pointers: Agentmap: in robots.txt, rel="ard" and
     rel="ai-catalog" in the Link header and the head.
   - robots.txt: the wildcard group first, 248 named groups, the shared training group (__usage_ai-training),
     both sitemap files named. license.xml in the RSL 1.0 shape. One policy value writes every place.
   - llms.txt in the v2 shape: one line per door under "If a user asks you any of these"; the full blocks moved
     to /llms-full.txt. /sitemap.xml lists the pages; /sitemap-md.xml the Markdown twins and root machine files.
     Nothing under /.well-known/ or /mcp/ is in a sitemap: those carry noindex, and the list is the whole list.
   - /about and /about.md: who publishes the hub, how a record is made, the terms, the contact.
   - Crawler proof: 43 agent tokens, the vendors' current range files, Web Bot Auth signatures (draft -01).
   The packs
   - Nothing invented: no contact, search description, status file, flows or icons unless the site has them;
     each withheld item is listed with its reason. A card ships only for an endpoint that answered the probe.
   - A site sheet, a work order and a manifest in every pack. Files an earlier pack left that this revision
     withdraws are recognised by their exact text, on the live site and in the local folder.
   - The installer writes only served files into a web root and keeps everything else in _packs\<host>\ inside
     this folder. A site's own files win: where a robots.txt is not a pack's, every file already in place is
     kept and only the missing ones are written. POST /v1/sites/{id}/pack rebuilds one pack, with no new briefing.
   - The hub's own door names one canonical (the home page) in the Link header as in the head.
   The checks
   - npm test (69 tests, no dependency) and a local rig: node test/rig.mjs, then the sweep against it.
   - tools\reachability.ps1: 22 hub sections, with the noindex audit, the internal-link check and the image check.

WHAT CHANGED (v2)
   Exposure: every door's page, title and llms.txt entry now carry the question the site itself declares it answers
   ("If a user asks: ..."), and llms.txt routes each question to its door. The hub announces each site's WHOLE
   sitemap to IndexNow under that site's key - every new or changed page, not only 31 homepages - and re-announces a
   door the hour its record changes. Search Console submission is built in (switch on in step 4).
   Trust: door numbers are permanent (a removed door answers 410, nothing renumbers); every door shows live / closed
   / not yet verified, closed doors are never sent as the answer and say "do not cite as live"; a failed fetch never
   wipes a record or fakes an "updated" date; languages show verified vs declared; the hub's own door is the home
   page, not one of "these sites". /match no longer answers off-topic questions (0 of 10, was 6 of 10) and keeps
   23 of 25 right; MCP, A2A and /match share one answer.
   Self-report: /status.json is a real health verdict; the daily CI turns red (GitHub e-mails you) when the sweep or
   the hub is red; nothing is pinged without a recent PASS sweep.
   Also from the earlier rounds: server-rendered pages + Markdown/JSON twins, the full machine surface (cards, MCP
   both eras, A2A, openapi, feeds, sitemap index), door thumbnails, bounded reads, capped batches.
